# 小説プレビュー

原稿テキスト（`.txt`）を、提出する PDF と同じ組版でページ表示する VS Code 拡張。

- **字数×行数で組む**: Word の「ページ設定」と同じ考え方で用紙・余白・字数×行数を決めると、そのとおりのページで縦書き（横書き）に組む。新人賞の規定書式（例: 42字×34行）で、提出物と同じ見た目を確かめながら書ける
- **プレビューのまま直せる**: ページ表示の段落をクリックすると、その場で編集できる。入力はそのまま原稿ファイルに入る
- **PDF と同じ組版**: プレビューと PDF 出力は同じパーサ・同じスタイルで組む。PDF は拡張だけで出せる
- **英語原稿にも対応**: 英訳など英語の原稿は自動で判定して、ペーパーバック風（6×9in など）に組む
- **原稿用紙換算**: ステータスバーに文字数・400字詰め換算・いまのレイアウトでの枚数を出す。エクスプローラーに章ごとの目次と文字数を出す

ルビ（`|漢字《かんじ》`）・傍点（`《《強調》》`）はカクヨム・小説家になろうと同じ書き方。[青空文庫の注記](https://www.aozora.gr.jp/annotation/)の主なものでも書ける。

## 入れ方

VS Code の拡張機能ビューで「小説プレビュー」を検索して入れる。

PDF 出力に使う Chrome は、初回の PDF 出力のときにダウンロードする（約180MB）。ほかに入れるものはない。

## 使い方

`.txt` のタブを右クリック →「エディターを指定して開く…」で「小説プレビュー」を選ぶ。作品のフォルダの `.vscode/settings.json` に `"workbench.editorAssociations": { "*.txt": "novelPreview.editor" }` と書けば既定になる。

レイアウトは作品の `novel.json` に保存される。

## 作品の設定

`novel.json` を開くと「作品の設定」の画面になる（プレビューのツールバーの「作品設定」、コマンド「作品の設定を開く」、エクスプローラーで `novel.json` を右クリックからも開ける）。タイトル・著者名などの作品情報、部の境界、出力（`"outputs"`）、英語の出力の項目をフォームで編集でき、変更はそのまま `novel.json` に入る。JSON のまま直したいときは「テキストで開く」。

- **部の境界**: 原稿ファイルの一覧で、新しい部を始めるファイルにチェックを入れる（`"parts"` に書かれる）。章番号は PDF と同じく「部-章」（部に章が1つなら「部」）になり、プレビュー・目次の番号も同じになる
- **出力**: 出力ごとに形式と、その形式に効く項目だけを出す。「既定」や空欄の項目は書かない（コマンドの既定や作品の項目を使う。空欄には効く値を薄く出す）。「作る」でその出力だけを作る

## 出力

「novel.json の出力を作る」（コマンドパレット・エディタのタイトルバーの「…」・エクスプローラーで `novel.json` を右クリック）で、`novel.json` の `"outputs"` に書いた出力を選んで作る。`novel build` と同じ処理で、出力ごとの設定もそのまま効く。形式は pdf / pdf-en / novel-pdf / epub / rtf / rtf-en / split / merge。

- pdf はその場で抜き出すページ（`--pages`）と先頭から組むファイル数（`--limit`）、split / merge は想定読者（`--target`）、merge はルビの括弧表記（`--ruby-parens`）を聞く。空欄なら付けない
- 出力先は設定 `novelPreview.outDir`（ワークスペースのフォルダから。既定は `out`）
- PDF・RTF は出力後に開く。設定 `novelPreview.openAfterExport` を false にするか、環境変数 `AUTO_OPEN=0` で開かない
- novel-pdf は Ghostscript（`gs`）、epub は `zip` を使う

「現在のレイアウトでPDFを出力」は、プレビューで見ているレイアウトのまま確かめるための PDF を `out/preview/` に出す。

## PDF との差

プレビューは Chromium の段組みでページを割る近似で、PDF とは数ページ単位でずれることがある。提出前の確認は「PDF出力」で行う。
